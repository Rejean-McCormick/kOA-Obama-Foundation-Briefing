# 05 — Evidence, Maturity, and Limits

The public work contains substantial implemented software, specifications, tests, documentation, research, educational material, and media. It also contains components that still require stronger deployment evidence, independent operation, institutional use, or commercial validation.

## Required distinctions

```text
documented ≠ implemented ≠ tested ≠ qualified ≠ deployed ≠ independently replicated ≠ socially validated
```

## Already public and inspectable

- many public GitHub repositories;
- active software components;
- automated qualification and CI in several repositories;
- architectural specifications;
- public context packs;
- structured source maps;
- educational content;
- research dossiers;
- scenario libraries;
- public websites and media.

The live repositories should be treated as the source of truth for current technical status.

## Still requiring independent proof

- real use by people other than the founder;
- bounded institutional deployments;
- measurable reduction in coordination burden;
- evidence that attribution and provenance survive real use;
- evidence that Smart Vote improves discovery in practice;
- language-by-language quality validation;
- repeatable deployment by non-founders;
- independent training and maintenance;
- operational evidence for exit and local autonomy.

This dossier does not claim every component is production-ready, every language has equal coverage, Smart Vote always finds an objectively best answer, or technical depth automatically produces social impact.
